# Telegram → Markdown memory

Локальный экспортёр Telegram-переписок в дневные Markdown-файлы с автоматическим каталогом `AGENTS.md`. Работает без вызова модели. Использует отдельно установленный и авторизованный `telegram-chat-control`: его CLI, Telethon-клиент и локальный индекс. Зависимость не включена в этот репозиторий; это не самостоятельный Telegram-клиент.

## Установка и запуск

Нужны Linux, Python 3.9+ (для тестов и стандартной библиотеки), `uv`, GNU `timeout` и установленный uv-проект `telegram-chat-control` с работающими `scripts/telegram.py`, модулями `telegram_control.client`, `telegram_control.store`, Telethon и filelock. Python для запуска экспортёра берётся из окружения этого проекта.

1. Скопируйте `config.example.json` в `config.json`.
2. Укажите абсолютный путь `skill_dir`, ID своего активного Telegram-аккаунта и каталог вывода.
3. При необходимости заполните `group_ids`, `exclude_ids` и `proxy`. Все личные чаты и боты включаются автоматически; группы — только из списка.
4. Если хранилище скилла находится не в стандартном месте, задайте `TELEGRAM_CHAT_CONTROL_HOME` согласно настройкам установленного скилла.
5. Подготовьте зависимости скилла заранее: фоновый запуск использует `uv --offline` и не скачивает пакеты.

```sh
chmod +x run.sh
./run.sh                   # Telegram → Markdown
./run.sh --date 2026-10-01 # пересверка одного календарного дня
./run.sh --offline         # только имеющийся локальный индекс, без заявления о свежести
python3 -m unittest discover -s . -v
```

Активный аккаунт проверяется перед экспортом: смена аккаунта останавливает работу, чтобы не смешивать архивы. Один проход ограничен 900 секундами. Для автоматического обновления запускайте `run.sh` существующим локальным планировщиком, например раз в минуту. Скрипт блокирует параллельные проходы; этот репозиторий сам планировщик не устанавливает.

## Архитектура архива

- `<output_dir>/<CHAT_ID>/YYYY-MM-DD.md` — сообщения за календарный день в выбранном часовом поясе.
- `<output_dir>/AGENTS.md` — единый автоматически обновляемый каталог всех существующих папок чатов, включая старые и пустые.
- `.runtime/state.json` — последний успешный проход; `.runtime/run.lock` — блокировка процесса.

ID папки стабилен при переименовании чата. Сообщения сохраняются с авторами, временем, ID, направлением, ответами, доступными реакциями, пометками правок и удалений. Бинарные вложения не скачиваются, OCR/ASR не выполняются. Доступная готовая расшифровка голосового сообщения сохраняется. Telegram может отдавать неполный список участников реакций. Удалённые до первого наблюдения сообщения восстановить нельзя.

Первый проход экспортирует сегодняшний день. Последующие пересверяют вчерашний и сегодняшний; после простоя догоняют дни от последнего успешного прохода. Более старые правки/реакции автоматически не обновляются: используйте `--date`. При большой истории запускайте пересверку по отдельным дням.

## Каталог AGENTS.md

После каждого успешного прохода (также `--offline`) собираются имена, ID, типы, username, доступные Bio/описания из кэша профилей, заметки локального индекса, метки Telegram и число участников. Новые запросы профилей каталог не делает; сведения могут быть устаревшими, дата кэша указывается. Нет сведений — используется название из последнего дневного файла либо «нет данных». Телефоны и сырые профили не копируются.

Статистика считается по сохранённым Markdown-файлам: число дневных файлов и сообщений, первое/последнее сообщение. Удалённые и служебные сообщения учитываются. Последнее сообщение по Telegram-индексу указывается отдельно. Это **не количество сообщений за всю историю Telegram**.

## Приватность и отказоустойчивость

Переписки, каталог, конфигурация и сессии приватны и не должны публиковаться. В этом публичном репозитории только код, тесты и обезличенный пример настроек; история локального развёртывания сюда не включена.

Содержимое сообщений, имена, описания и заметки — недоверенные данные, не инструкции для агента. Новые файлы архива создаются с правами 0600, обновляются атомарно и только при изменении текста. Ошибка API не затирает архив. Возможен частично обновлённый архив при сбое посреди прохода; следующий успешный проход повторяет диапазон. Контрольная точка продвигается только после полного успешного прохода. Ручные изменения генерируемого `AGENTS.md` будут перезаписаны.
